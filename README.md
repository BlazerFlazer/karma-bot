# KARMA SYSTEM 2.0 и KARMA CONTROL

Русскоязычный Discord-бот для семьи KARMA на GTA 5 Majestic RP. Один процесс Node.js обслуживает команды, приватные обращения, игровые мероприятия и очередь задач. Постоянные данные и расписание находятся в SQLite. Администратор управляет сервером через `/setup` и `/dashboard`.

## Веб-панель KARMA CONTROL

В панели доступны студии тикетов, тиров и сообщений, приватные черновики, публикация с подтверждением, очереди обращений и набора, состав семьи, события, роли и справочник команд. Рабочие данные общие с Discord-ботом. [Руководство сотрудников](docs/KARMA-CONTROL.md) · [Развёртывание и OAuth](docs/HOSTING-CONTROL.md)

Локальный предпросмотр экрана входа запускается командой `npm run control:preview`. Интерфейс на русском языке использует локальные шрифты и загружает модули разделов по мере перехода.

## Локальный запуск на Windows

Установите Node.js 22.16 или новее. Проект проверен на Node.js 22.22.3. Перейдите в папку с `package.json` и выполните в PowerShell следующие команды.

```powershell
node --version
node -e "console.log(typeof require('node:sqlite').DatabaseSync)"
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
npm.cmd ci
npm.cmd run migrate
npm.cmd test
```

Проверка SQLite должна вывести `function`. Встроенный драйвер поставляется вместе с Node.js. Предупреждение Node 22 об экспериментальном API допустимо. На Windows вызов `npm.cmd` работает и при ограничениях выполнения PowerShell-скриптов.

После настройки приложения заполните локальный `.env`. Затем зарегистрируйте команды и запустите бота.

```powershell
npm.cmd run deploy:commands
npm.cmd start
```

## Приложение Discord

1. Откройте Developer Portal, выберите **New Application** и задайте название KARMA SYSTEM. В **General Information** скопируйте **Application ID** в переменную `APPLICATION_ID`. [Discord Developer Portal](https://discord.com/developers/applications)
2. Откройте **Bot**, создайте или настройте bot user. Получите токен через **Reset Token**. Локально внесите его в `DISCORD_TOKEN`, на хостинге используйте секрет окружения. Сброс токена требует обновления переменной и перезапуска процесса. [Руководство Discord](https://docs.discord.com/developers/quick-start/getting-started)
3. Для приветствий, прощаний и авторолей включите **Server Members Intent** в разделе **Privileged Gateway Intents**, затем установите `MEMBERS_INTENT=true`. Для текстовых фильтров и содержимого обычных сообщений в транскриптах включите **Message Content Intent** и задайте `MESSAGE_CONTENT_INTENT=true`. Учёт голоса использует события состояния голосовых каналов. Presence Intent боту не нужен. [Документация Gateway](https://docs.discord.com/developers/events/gateway)
4. В **Installation** настройте **Guild Install** с областями `bot` и `applications.commands`. Выберите права для используемых модулей. Откройте сгенерированную ссылку установки, выберите тестовый сервер и подтвердите установку. Альтернативный способ сформировать ту же ссылку доступен через **OAuth2 → URL Generator**. [Установка приложения на сервер](https://docs.discord.com/developers/quick-start/getting-started)
5. Для быстрой регистрации на тестовом сервере включите в Discord режим разработчика, скопируйте ID сервера в `GUILD_ID` и выполните `npm run deploy:commands`. Пустой `GUILD_ID` выбирает глобальную регистрацию. Регистрация заменяет набор команд этого приложения в выбранной области. Повторяйте её при изменении манифеста команд. Переключение области не удаляет ранее зарегистрированные команды другой области.

## Развёртывание на Bot-Hosting.net

1. Создайте аккаунт, откройте панель и выберите создание **Application Deployment**. Для одного экземпляра бота подходит Node.js runtime. Бесплатный тариф указывает 256 MB RAM, 25% CPU, 512 MB хранилища и один deployment. Провайдер указывает ручное продление каждые четыре дня. [Тарифы](https://bot-hosting.net/pricing) · [Создание deployment](https://bot-hosting.net/docs/guides/create-a-deployment)
2. Выберите ZIP-архив проекта либо загрузите исходники через **Files** или SFTP. В корне deployment должны лежать `package.json` и `package-lock.json`, рядом каталоги `src`, `web` и `scripts`. В архив не включайте локальный `.env`, `node_modules` и рабочие копии БД. [Настройка deployment](https://bot-hosting.net/docs/guides/set-up-a-deployment)
3. Выберите образ Node 22 с версией не ниже 22.16 либо совместимую более новую версию. В Shell проверьте `node --version` и `node -e "console.log(typeof require('node:sqlite').DatabaseSync)"`. Совместимость локальной версии проверена. Доступные образы и путь постоянного хранилища проверьте в созданном контейнере.
4. В настройках окружения задайте `DISCORD_TOKEN` как секрет, `APPLICATION_ID`, при необходимости `GUILD_ID` и параметры intents. Для `DATA_DIR` выберите доступный на запись каталог постоянного хранилища. По умолчанию используется `./data` относительно рабочей директории процесса.
5. Установите зависимости по lock-файлу командой `npm ci --omit=dev`. Если панель устанавливает пакеты при старте, проконтролируйте успешную установку по консоли. В **Startup** укажите `npm start`, если поле принимает команду. Если панель запрашивает **Entry File / STARTUP_FILE**, укажите `src/index.js` и задайте `NODE_OPTIONS=--max-old-space-size=132`. [Настройки запуска и установки](https://bot-hosting.net/docs/guides/set-up-a-deployment)
6. Выполните `npm run migrate` и `npm run deploy:commands` в Shell. Команды также можно зарегистрировать с локального компьютера для того же приложения. Запустите deployment. В консоли появится событие `ready`. Выполните `/bot status` и `/diagnostics`. После планового перезапуска проверьте прежнюю панель и сохранённую привязку канала.

## Первая настройка в Discord

1. Войдите владельцем или администратором и вызовите `/setup`. В разделе ролей последовательно привяжите руководителей, проверяющих, поддержку, модераторов, Recruit и Member. Назначьте сотрудникам соответствующие роли в Discord.
2. Для каждого назначения выберите существующую роль или канал. Кнопка **Создать…** принимает имя, затем показывает подтверждение. Мастер проверяет сохранённую привязку и совпадение по названию. Если одинаковых названий несколько, выберите ресурс вручную. Для замены привязки используйте селектор существующих ресурсов.
3. Привяжите категории активных обращений, набора, тиров, жалоб, обращений к руководству и архива. Настройте каналы результатов, поддержки, публикаций и журналов. В закрытых журналах явно запретите **View Channel** для `@everyone`. Просмотр разрешайте боту и только ролям, имеющим право видеть этот тип обращения.
4. Для жалоб на администрацию выделите отдельный закрытый текстовый журнал с доступом вышестоящих ролей. В `/dashboard → Обращения → Настроить тип или анкету` откройте код `staff` и в поле `log` введите ID этого журнала строкой. Бот откажется выкладывать транскрипт в журнал с посторонними разрешениями. Администраторы Discord сохраняют платформенный доступ к закрытым каналам.
5. В `/dashboard → Система тиров` создайте тир. Задайте его код, название, требования, ID выдаваемой роли, порядок, интервал повторной заявки в секундах и роли проверяющих. Большее значение порядка означает более высокий тир. Участникам доступны коды через `/tier list`.
6. Опубликуйте `/ticket panel type:join` в канале заявок. Для меню всех типов используйте `/ticket panel` без параметра. Для верификации сначала укажите `verificationRole` в настройках ролей, затем выполните `/rolepanel verify`.
7. Вызовите `/diagnostics`. Пройдите пробную заявку от обычного участника и рассмотрите её отдельной учётной записью сотрудника. Проверьте отсутствие видимости у постороннего участника. В публичном результате должны отображаться только номер, заявитель и решение.

### Настройка анкет

Для уведомлений проверяющих Discord должен разрешать боту упоминание выбранной роли в канале обращения. В **Настройки → Набор и тиры** поле `removeOnAccept` задаёт роли для снятия после принятия. Для дополнительной роли Guest можно указать её ID строкой. В **Настройки → Очки и награды** доступны очки за обычное мероприятие и тренировку, пороги достижений и разовые бонусы.

В редакторе типов задаются название, описание, emoji, приветствие, категория, режим, доступ, лог, приоритет, лимиты, интервал и вопросы. Для нового типа введите свободный код. Встроенные коды вида `join`, `tier`, `upgrade`, `complaint`, `staff` связаны со специализированными обработчиками. `access` принимает ключи из мастера или строковые ID ролей. `category`, `parent` и `log` принимают соответствующий ключ или строковый ID. `autoClose` задаётся в часах бездействия, ноль отключает автозакрытие. `cooldown` задаётся в секундах.

Каждый вопрос имеет уникальный `key`, русский `label` и флаг `required`. Обязательные вопросы специализированных анкет сохраняются при редактировании. После пяти полей участник получает приватную кнопку продолжения. Снимок анкеты хранится с обращением. Полные длинные ответы также поступают в приватный канал файлом. Проверка доказательств принимает HTTPS и точное совпадение имени хоста. Доступность видео оценивает сотрудник.

По умолчанию создаётся приватный текстовый канал с явными разрешениями. В режиме `thread` участнику нужны просмотр родительского канала и отправка сообщений в ветках. Проверяющим требуется управление ветками в родительском канале. Discord предоставляет доступ менеджерам веток и администраторам. Для жалоб на администрацию используется приватный канал. [Права приватных веток](https://docs.discord.com/developers/topics/threads)

## Данные и восстановление

SQLite применяет пронумерованные миграции на старте. Snowflake ID и игровые статики хранятся строками. Основная БД находится в `DATA_DIR/karma.sqlite`. Планировщик выбирает до восьми задач за проход каждые 15 секунд. После пяти неудачных попыток задача видна в **Резервные копии → Задачи с ошибками**. Исправьте права или привязки и выберите задачу для повторения. Причина технической ошибки и расположение кода доступны в ротационном `runtime.log`.

`npm run backup` и `/backup create` делают согласованный SQLite-снимок через `VACUUM INTO`, включая зафиксированные изменения WAL. Хранятся до пяти копий в `DATA_DIR/backups`. Команды копирования в Discord доступны владельцу установки с одним сервером. Восстановление проверяет схему, целостность, внешние ключи и принадлежность серверу, просит персональное подтверждение и сначала сохраняет текущую БД. Откат данных затрагивает SQLite. Уже опубликованные сообщения и выданные роли находятся в Discord, их состояние после отката проверьте отдельно.

Для переноса остановите исходный процесс после создания свежего снимка. Скачайте снимок, на новом хосте остановите бот и сохраните прежний каталог данных отдельной копией. Положите снимок под именем `karma.sqlite` в пустой постоянный `DATA_DIR`, настройте секреты, выполните миграцию и запустите один экземпляр. Проверьте `/diagnostics`, старую кнопку и очередь. При обычном обновлении загрузите исходники и lock-файл, сохраните текущий `DATA_DIR` и повторите `npm ci --omit=dev`. [Документация SQLite WAL](https://sqlite.org/wal.html)

Транскрипт содержит анкету и до 300 последних сообщений. На фрагменты переписки отводится до 480 000 байт. Для вложений сохраняются названия. По сроку хранения бот удаляет свой файл из закрытого журнала, очищает приватные ответы в закрытых записях SQLite и старые записи аудита. Копии БД имеют собственную ротацию. История внутри самого Discord-канала остаётся до его удаления уполномоченным сотрудником с подтверждением. Логирование текста изменённых и удалённых сообщений включается отдельно и ограничено семью днями.

## Диагностика запуска

| Симптом | Что проверить |
| --- | --- |
| `ERR_UNKNOWN_BUILTIN_MODULE` для SQLite | Версию runtime в **Startup** и результат проверки `DatabaseSync` |
| Бот не выходит в сеть | `DISCORD_TOKEN`, секреты deployment, перезапуск после изменения окружения |
| Gateway 4014 | Соответствие включённых intents в Developer Portal и переменных окружения |
| Команды отсутствуют | Верный `APPLICATION_ID`, выбранная область `GUILD_ID`, права установки и успешный `deploy:commands` |
| Discord 50013 / Missing Permissions | Иерархию роли бота и сотрудника, индивидуальные запреты канала и `/diagnostics` |
| Транскрипт не отправляется | Канал логирования типа, запрет просмотра для `@everyone`, посторонние разрешения, права бота Attach Files и Send Messages |
| В транскрипте пустой текст | Message Content Intent в портале и процессе. Старые удалённые сообщения API уже не возвращает |
| Бот не может записать БД | Права каталога `DATA_DIR`, свободное место, один запущенный экземпляр и сохранность каталога между рестартами |
| Решение принято, DM не пришло | Настройки приватности получателя. Статус решения доступен в записи заявки и аудите |
| Превышение RAM | `/bot status`, метрики deployment под реальной нагрузкой, число серверов и интенсивность крупных розыгрышей |

## Проверки и архитектура

`npm run check` проверяет синтаксис исходников, скриптов и тестов. `npm test` запускает unit- и интеграционные проверки с временной SQLite. `npm run measure` загружает все модули и Discord-клиент без входа в Gateway, пишет 10 000 событий в отдельную временную БД и выводит RSS и пиковую память процесса. Метрики реального deployment доступны в `/bot status`.

Маршрутизатор в `src/core/router.js` обслуживает slash-команды, контекстные меню, кнопки, селекторы и формы. Центральные построители сообщений находятся в `src/core/ui.js`, проверка полномочий в `src/core/access.js`, конфигурация в `src/core/config.js`. Прикладные функции расположены в `src/modules`. Драйвер и схема находятся в `src/database`, планировщик, транскрипты и доставка аудита в `src/services`. Доступ к Discord изолирован от открытия и миграции БД. API, OAuth2 и права KARMA CONTROL находятся в `src/control`, веб-интерфейс и локальные ресурсы — в `web/public`.

Результаты прогонов, ограничения и оставшиеся проверки приведены в [PROGRESS.md](PROGRESS.md). Этапы разработки перечислены в [DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md).
