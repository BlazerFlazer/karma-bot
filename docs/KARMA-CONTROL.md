# KARMA CONTROL 2.0

KARMA CONTROL объединяет веб-студии, рабочую очередь заявок и справочник команд с существующим KARMA SYSTEM. Бот и HTTP-сервер работают в одном процессе Node.js и пользуются одним файлом SQLite. Версии схемы 5 и 6 добавляют роли, сеансы, черновики, подтверждения, историю публикаций, заметки и настройки сотрудников.

## Первый вход

1. Подключите домен и OAuth на действующем deployment по [инструкции хостинга](HOSTING-CONTROL.md). Боту нужны права в каждом канале, с которым предстоит работать.
2. Войдите в браузере с аккаунта фактического владельца Discord-сервера. В разделе «Роли и права» выберите роль по имени или ID, примените пресет и проверьте отмеченные операции. Изменения вступают в силу после подтверждения.
3. Для сотрудника набора в `/setup` предусмотрена отдельная привязка «Recruit · сотрудник набора». Стандартный кандидат Recruit получает доступ к панели только при явном назначении. Для работы с заявками дайте сотруднику право просмотра набора, роль проверяющего конкретной анкеты и доступ к её каналу. Принятие и отклонение настраиваются отдельно.
4. Начните с обзора. Счётчики, последние действия, события и назначенные обращения берутся из базы и учитывают доступ сотрудника. Измените тему, порядок виджетов, избранное и уведомления в «Мой профиль». Поиск открывается через Ctrl+K или Cmd+K.
5. Для проверки экземпляра веб-интерфейса без Discord выполните `npm run control:preview` и откройте `http://127.0.0.1:4173`. Эта команда поднимает экран входа на временной базе. Порт меняется через `CONTROL_PREVIEW_PORT`. Для проверки закрытых разделов с изолированной гильдией предусмотрена команда `npm run test:ui`.

## Подготовка панели

- В студии тикетов выберите готовую анкету из «Шаблоны». В разделе «Конфигурация» настройте вопросы, подсказки, обязательность, проверяющих, роли заявителей, канал или ветку, журнал, приоритет и интервал подачи. Действия сотрудников можно менять для каждого типа. Анкеты более пяти вопросов бот делит на этапы.
- В студии тиров нажмите «Создать тир». **Код придумываете вы**. Например, `tier1` для первого тира или `silver` для серебряного. Первый символ — строчная латинская буква. В остальных позициях разрешены строчные латинские буквы, цифры, дефис и подчёркивание. Максимум 30 символов. Действующий код откроет соответствующую конфигурацию. Его можно посмотреть на карточке тира или в `/tier list`. Укажите отдельную выдаваемую роль, проверяющих и требования. Для индивидуальной анкеты откройте её настройки в редакторе тира. Ссылки на доказательства проверяются по точному имени домена.
- В студии сообщений выберите шаблон, заполните заголовок и описание, добавьте поля, изображение, ссылки или меню. Переменные заполняет сервер. В режиме Components V2 доступны контейнер, текст, разделитель, секция с миниатюрой, медиагалерея и текстовое вложение. Файл собирается из введённого текста. [Поддержка компонентов в Discord](https://docs.discord.com/developers/components/reference)
- Предпросмотр показывает данные, подготовленные тем же обработчиком, который составляет payload для Discord. Переключите размер устройства или запустите локальный симулятор обращения. Шрифт интерфейса задаётся в профиле. Окончательное отображение текста, внешних медиа, упоминаний и emoji зависит от клиента Discord.
- «Сохранить черновик» сохраняет личную версию. «Общий доступ» открывает запись выбранным ролям с доступом к студии. Для изменения общего черновика нужно также право совместной работы. Если коллега изменил версию, редактор сообщает о конфликте. Вторая запись поверх первой автоматически не производится.
- «Сохранить настройки» применяет конфигурацию в боте. Для существующих тикетов сохраняется снимок правил на момент открытия. Новые анкеты используют обновлённый тип. При изменении прав заявителей, проверяющих или каналов типа требуется разрешение настройки сервера.
- «Подготовить к публикации» проверяет готовность. Затем выберите «Опубликовать в Discord», укажите канал и откройте итоговый предпросмотр. Только подтверждение в этом окне отправляет сообщение. Для обновления выполните те же шаги в исходном канале. В центре публикаций доступны канал и ID сообщения. Для перехода между форматами Embed и V2 создайте копию панели.
- Когда Discord не подтвердил доставку, журнал сохраняет результат попытки. После истечения короткого окна безопасного повтора проверьте исходный канал. Если опубликованное сообщение было удалено, создайте копию черновика и подтвердите новую публикацию.

## Работа сотрудников

«Входящие» и «Набор» показывают доступные обращения. Откройте карточку, чтобы прочитать ответы, историю, до 25 последних сообщений и доступные вложения. Содержимое сообщений зависит от настроенного Discord Message Content intent. Внутренняя заметка сохраняется в базе. Кнопка ответа отправляет сообщение в канал от имени бота с указанием автора. Ссылка на транскрипт появляется после создания и при доступе к каналу журнала.

«Создать тикет» создаёт настоящее обращение после выбора пользователя Discord, категории, приоритета, заполнения анкеты и подтверждения. Для внутреннего обращения выбирают себя и тип поддержки. Симулятор в студии использует только состояние браузера.

Изменения из Discord видны при открытии раздела. Активные списки и обзор обновляются примерно раз в минуту, когда вкладка открыта и сотрудник не работает с формой. В карточке обращения есть кнопка «Обновить». Реестр команд строится из зарегистрированных обработчиков. Независимые разрешения Discord, состояние модуля и объектные ограничения продолжают действовать.

## Проверка перед включением на сервере

Перед обновлением сохраните снимок действующей базы. Восстановление копии первой версии возвращает бот к данным этой копии и очищает таблицы веб-панели, появившиеся позднее. Перед операцией бот делает страховочную копию текущего состояния. После восстановления пользователи заново входят через Discord. Роли и сообщения, уже созданные в Discord, требуют отдельной сверки.

`npm run check`, `npm test`, `npm run test:ui` и `npm ls --omit=dev` запускаются из корня проекта. Для браузерного прогона нужен Chromium, Chrome или Edge. Через `CHROME_PATH` можно указать исполняемый файл. Тест самостоятельно запускает браузер с временным профилем, создаёт изолированную SQLite, проверяет экраны разных размеров и публикацию в адаптер. Производственные маршруты входа остаются теми же.

Сначала используйте отдельную тестовую гильдию. Проверьте официальный OAuth callback, отказ для рядового участника, отзыв роли во время сеанса, чтение закрытого тикета и доставку одной панели в выбранный тестовый канал. После перезапуска проверьте старые кнопки, файлы базы, обновление сообщения и замеры памяти на вашем тарифе.
